# 05 — Validate all eight settings and verify commissioning writes

## Inputs

Consume `rtu-codec` and `measurements`. Apply [COMMON](COMMON.md). Use [table 2 for both models](../reference/protocol/registers.csv), [configuration evidence and conflicts](../reference/measurement-and-configuration.md), [FC06 examples](../reference/protocol/modbus_vectors.csv), the [operation matrix](OPERATIONS.csv) and the [public conventions](CONVENTIONS.md). Produce `configuration`.

## Work

1. Expose `Setting::{Address, Baud, SwitchPolarity, SwitchThreshold, Angle, UartUnit, Noise, Range}` in the public library. Provide a typed value conversion, addressed FC03 read builder, checked FC06 write builder and readback decoder for every selector on both models. Share this metadata between the library and the full Arduino and ESP-IDF examples. Preserve raw readbacks, unknown enum values and their interpretation. Track desired, observed and verified configuration independently. Startup performs zero writes.

   | Selector and CLI key | Wire register, value and semantics |
   | --- | --- |
   | `Address` / `address` | `0x0200`. Factory 1. Assignable 1..247 in the default standard profile and 1..254 in isolated DFRobot addressing. The distinct broadcast destination is 255. |
   | `Baud` / `baud` | `0x0201`. Codes 2..9 mean 4800, 9600, 14400, 19200, 38400, 57600, 76800 and 115200 bps respectively. Default 9 at 8N1. Commands take baud in bps. Show the backend's separately supported subset. |
   | `SwitchPolarity` / `polarity` | `0x0205`. Below threshold, 0 specifies low output and 1 high (default). Equality behavior unspecified. Show the switch-mode applicability. |
   | `SwitchThreshold` / `threshold` | `0x0206`. 30..3000 mm on SEN0591 and 30..5000 mm on SEN0592. Factory threshold unspecified. Show the switch-mode applicability. |
   | `Angle` / `angle` | `0x0208`. Levels 1..4, default 4. Use the model-specific angles and SEN0592 single/horizontal/vertical labels from table 2. Preserve source differences. |
   | `UartUnit` / `uart-unit` | `0x0209`. Wire 0 is mm and 1 is µs (`mm` and `us` at the CLI). Applies to automatic/controlled UART output. Factory setting unspecified. |
   | `Noise` / `noise` | `0x021A`. Levels 1..5, default 1. Document the five supply examples and the unspecified size and direction of the effect on beam angle. |
   | `Range` / `range` | `0x021F`. SEN0591 levels 1..4, default 4. SEN0592 levels 1..5, default 5. Label nominal range separately from rated measuring distance. |

2. Implement the public `buildWriteSingleRegister` for all eight settings. Validate explicit SKU, address policy, access, selector, units and value before emitting bytes. All eight have the same preview, confirmation and observed-value readback path. For the three conditional settings expose both register access and the documented mode of the physical output. A unit may return an actual Modbus exception, mismatch or timeout. Report the observed result with details. The four-wire RS485 pinouts identify VCC, GND, A and B. The sources give no switch/UART mode-selection command. FC03 units in table 1 remain constant at both values of the UART unit setting.
3. Keep `AddressPolicy::StandardUnicast` as the default for current and target addresses 1..247. Apply `AddressPolicy::DFRobotIsolated` explicitly to use current or target addresses 248..254 on a declared single-device bench. Both policies reject 0 and 255 as assigned endpoints. Encode the address change, read the register at its new address, and allow an extended endpoint to be changed back to a standard address. The isolated mode is selected by the application. Standard and FieldCore admissions retain their own address limits.
4. For an addressed change, retain the original binding, intended endpoint, TX progress, acknowledgement shape/origin, independent FC03 comparison, cleanup and final endpoint. For ordinary settings verify the same register on the same binding. For address, verify `0x0200` at the new address and compare the returned word with that address. The vendor example echoes the old address. For baud, verify `0x0201` at the selected new rate with the same slave. The change is immediate and the ACK rate is unknown. Ensure the owner can use the new baud before transmission. A genuine FC06 echo leaves verification pending. Following an ambiguous/lost ACK, allow an explicit bounded readback after line settlement. Keep the underlying evidence with `CONFIG_MISMATCH` or `LINK_LOST` where applicable. The owner implements UART changes and timeouts. No write replay, automatic rollback, scanning or persistence claim from a live readback.
5. Provide `buildVendorBroadcastWrite` as a distinct checked FC06 builder taking an explicit SKU, writable setting and typed value. Its destination is fixed at 0xFF. Apply the same value bounds, including assignment restricted to 1..254 and a backend-supported new baud in the example. The owner requires a declared isolated device, the DFRobot profile, preview/confirmation and one maintenance grant. Record TX progress/drain and any bytes observed separately. Complete the **send operation** after TX settlement. The manuals name 0xFF without specifying a supported function set, responder address, acknowledgement rules or an example exchange. Preserve the effect as unverified. A subsequent explicit addressed FC03 may establish one setting at one endpoint. Neither silence, local echo nor unsolicited bytes establish execution. Keep zero outside the SEN059x destination APIs and omit broadcast FC03.

## Acceptance

- Begin with a previously verified setting. A preview, refused command or proven zero-byte TX preserves that trust. Once a write may have reached the unit, preserve the previous observed word and timestamp as history and mark the affected setting unconfirmed. For address or baud, also mark the endpoint identity unconfirmed and retain the old and intended settings for recovery. Test this for addressed and 0xFF sends, including loss of the ACK and failure of readback. Only an attributable addressed FC03 can establish the current observed value, and a mismatch leaves the requested change unverified.

- Compile a consumer against the public umbrella and drive all eight typed reads and all eight checked writes on **each** SKU. For each setting cover valid boundaries, just-outside values, unknown raw readback, a valid FC06 echo and comparison with an independent FC03 value. Check full bytes/CRC against independent vectors. Replay manufacturer examples 4–6. Run the four stage 04 measurement decodes after both UART-unit values. Reject attempts to write all four measurement registers and any undocumented register before TX.
- Test polarity 0/1 and raw 2, threshold 29/30/3000/3001 and 5000/5001 by model, UART unit mm/us and unknown raw 2, all eight baud codes, all angle/noise levels and SEN0592-only range level 5. Exercise every setting through addressed and explicit vendor-broadcast builders. Expose mode applicability, missing defaults and acknowledgement uncertainty in results or public descriptors.
- Test extended-address transitions 247→248 and 254→1, addressing/read/write/readback while at 254, and rejection of 0 and 255 assignments. Verify a standard policy caller rejects 248..254. Check that an explicitly built 0xFF transmission can neither enter a unicast wait-for-reply path nor create verified state, including on a byte-identical echo, silence, short TX or a frame from an unexpected address.
- Script lost ACK followed by matching verification, wrong echo-register/value, verified mismatch, device exception, power interruption and silence after a baud/address change. A failed admission sends zero bytes and preserves the binding. Keep successful physical output, persistence, and the unit's implementation of the vendor destination as distinct evidence that requires a suitable fixture.
