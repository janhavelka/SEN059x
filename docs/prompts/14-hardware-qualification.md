# 14 — Qualify the sensor and bus on a named bench

## Inputs

Apply [COMMON](COMMON.md). Consume `runner-evidence` and `verified-package`. Read the [hardware ratings](../reference/hardware.md), [measurement tables](../reference/measurement-and-configuration.md), [wire timing](../reference/protocol/Modbus_RTU_notes.md) and [coverage index](COVERAGE.md). Produce `bench-evidence` for the actual setup and model tested.

## Work

1. Identify each unit by marking or installation record. Record SKU, cable/pin mapping, reference ground, termination, topology, transceiver, direction mode and echo behavior, actual supply, adapter, board, firmware/SDK, console path, target geometry and clock resolution. SEN0591 permits 3.3–12 V and SEN0592 permits 3.3–24 V. Allow the published power-up delay of up to 1000 ms before the first command. Use one owner, a known unicast endpoint and one unit at address 1 when starting with factory settings.
2. On each available SKU read all four measurement registers individually at multiple measured target distances, including the near limit and a representative far target within its rating. Record raw requests/replies including CRC and the reference distance and uncertainty. Vary target/beam geometry for no-return observations. Record independent temperature alongside the positive example. Only interpret sign with controlled subzero evidence and a separate reference. Mark unexercised conditions explicitly.
3. Time TX start, end of shift-out, DE/RX handover, first/last response byte and observed frame boundary at the available timestamp precision. Record owner timeout separately. Compare measurement windows, all four SEN0591 per-level estimates when available, serial time at the selected rate and the SEN0592 language-edition differences. Evaluate the 3 m rating and the approximately 3.5 m SEN0591 level-4 label separately. Record actual samples and distribution before revising a limit.
4. Carry all eight configuration settings per SKU into the fixture worksheet. For every register record the original addressed FC03, the actual word and any exception. On an authorized isolated bench, preview the typed change, confirm once, read back the same register independently at the expected endpoint and restore/verify the original. If the original cannot be read or restored reliably, record why that change was left untested. Record address/baud endpoints before and after each change, the observed ACK address/rate if known, possible local echo and any unsuccessful restoration. Exercise each hardware-supported sensor baud and report missing rates separately. Test persistence with a separate authorized power cycle and read where practicable.
5. Verify recovery after a missed reply, wrong/late reply or disconnect and reconnection. Keep deliberate malformed traffic in the offline suite unless the specific bench setup can inject it separately. With multiple uniquely addressed units, run bounded interleaved operations and verify no cross-assignment or starvation. When a four-head fixture is available, vary emitter placement/sequence and record cross-talk, intervals, target and geometry. Keep scheduling results separate from acoustic behavior.
6. For switch polarity, switch threshold and UART unit, qualify addressed register writes and readbacks on each RS485 unit. Record what the actual connector exposes. Qualify electrical polarity, threshold behavior or UART-unit output only on a separately identified fixture that exposes the documented mode. Record the physical effect as unobserved on a four-wire unit where that output is inaccessible. Check the Modbus measurement units before and after a UART-unit change. Keep any DYP family fixture evidence separately identified by part.
7. Exercise the separate isolated DFRobot addressing path on one known device, where authorized. Check transition to an extended address, addressed readback there and restoration to the original address. If testing 0xFF, save the existing setting, transmit one checked FC06, capture TX, drain, possible local echo and all returned bytes. Explicitly read the target register at a known addressed endpoint and restore/verify through that addressed path. Record which actual setting the broadcast frame attempted. An absent reply or an identical echo has no authority to mark the command as executed. Other settings or SKUs need their own evidence.
8. Compare hardware behavior through the actual Arduino and IDF applications and the independent direct read-only probe in separate runs. Use the [operation matrix](OPERATIONS.csv) as the worksheet for both full applications. Record which combination of command, adapter, board, framework and SKU was actually connected. A USB polling timestamp may support end-to-end latency and still leave RTU wire closure unmeasured.

## Acceptance

On an available isolated unit, use the explicit multi-word `readregs` diagnostic on a documented contiguous range. Record request, full ordered reply or exception, timing, model and configuration. Use a configuration-only span first. Label any triggered measurement span separately, preserving the unknown acquisition order. A device rejecting a well-formed span is a useful per-SKU outcome.

For each SKU publish observed pass, observed fail or untested/blocked for all 20 addressed operations, extended addressing and the eight isolated send-only keys. Add the test conditions, evidence path and unresolved question. Record register readback, functional effect, restoration and power-cycle persistence independently. Use a raw capture, logic trace or other independent reference for conclusions about ACK baud, timing, sign or sentinel. Missing hardware leaves its specific rows open. Stage 15 may still review the tested software.

## Delegation and self-audit

Apply the [stage audit](AUDIT.md). Have the reviewer match every physical claim to the SKU, setup, raw capture and independently observed outcome. Record each missing unit or inaccessible output as a physical evidence gap.

## Handoff

Record `bench-evidence` or the partial/blocked fixture status in [PROGRESS](PROGRESS.md). Provide a reproducible bench report by SKU plus a bounded list of open observations and any justified corrections to the audited reference.
