# SEN059x example console contract

Use this contract in stages 09–14. The two bench applications share a command registry, parser, human renderer, machine renderer and command handlers under `examples/common/`. The registry drives dispatch, grouped help and the published command reference. The application supplies its board identity, byte input/output, monotonic clock and the owner from stage 07. FieldCore-node can use the public library without linking any console code.

The command names and grouped help follow SHZK-PT and TMP1x2. The correlated machine channel borrows the explicit request prefix from MotorControl-RS and the boot/session distinction from DP8382x. The schema and commands below are the SEN059x design. [SHZK-PT command table](https://github.com/janhavelka/SHZK-PT/blob/59d76c502a90bef8038ced2b72a2d50df98184e9/examples/01_basic_bringup_cli/Commands.inc) · [TMP1x2 processor](https://github.com/janhavelka/TMP1x2/blob/afd50889312f6e218a6a34eca687e3e8547d8b40/examples/common/Tmp1x2Cli.cpp) · [MotorControl-RS console](https://github.com/janhavelka/MotorControl-RS/blob/08a88ebb422d1a9f8df9c3036faabf82b3a0983e/examples/probe_cli/ProbeConsole.cpp) · [DP8382x console contract](https://github.com/janhavelka/DP8382x/blob/683270be5755711d3f49613320b0e3979c0a153e/docs/prompts/CLI_CONTRACT.md)

## Human console

After an addressed or vendor write that may have reached the sensor, passive `settings` shows the old value and observation time as historical and the affected setting as unconfirmed. For address or baud, `status` also labels the last-known and intended endpoints until an addressed readback establishes the current one. A preview or proven zero-byte send preserves prior trust. Put the same distinctions in machine results.

Start in plain text with `> ` and `=== SEN059x CLI Help ===`. Support `help`, `?` and detailed help for a command or setting, including `help config set polarity` and `help broadcast set`. Group and align usage with a one-line description. Detailed help gives arguments, units, SKU limits, bus effects and whether the command starts ranging. Show the selected model, address policy, slave and host baud on request. At startup the SKU is unselected unless the application explicitly supplies it. Attaching a terminal performs zero sensor transfers.

| Group | Commands and effects |
| --- | --- |
| Console | `help [command]` (`?`), `version` (`ver`), `color [on\|off]`, `verbose [on\|off]`. Show public library version, application revision/dirty or unknown, framework/version, target, board and schema. Color defaults off, styles human fields only and resets after each field. Verbose adds bounded human TX/RX or watch diagnostics, without changing any request, deadline or machine record. |
| Target | `model [SEN0591\|SEN0592]`, `profile [standard\|dfrobot-isolated]`, `useaddr <address>`, `host [baud <rate>]`. These select local context only. Fixed 8N1. Report the adapter's supported baud rates and any failure to apply a setting locally. Reject changes during active work or line recovery. A successful change to the binding creates a new generation and invalidates target-dependent evidence. |
| Cached | `status` shows binding, owner and current operation. `drv` shows last request/function/register, timing, primary and cleanup results. `health` shows `DriverState` and the public health fields. `stats` shows owner/transport counters separately. `settings` shows desired/observed/trusted configuration with validity per register. `latest [processed\|realtime\|temperature\|echo]` (alias `sample`) shows cached samples. All are passive, including while a request runs. |
| Measurements | `read <processed\|realtime\|temperature\|echo>` submits one addressed FC03. `watch <kind> <count> <interval_ms>` submits a finite series through the same owner. Accept counts 1..100 and intervals 1..60000 ms as **example limits**. Schedule at most one due read, account for actual completion and skipped intervals, and never build a catch-up queue. Watch returns completed/failed/skipped counts, its last result and elapsed time. |
| Configuration | `config read <key\|register>` reads one configuration word by its key below or numeric register address. `readreg <register>` reads one of all twelve published words. Both use the same typed decode and side-effect rules as their named equivalents. Its help identifies the three ranging triggers. `readbaud` is an alias for `config read baud`. |
| Block diagnostic | `readregs <start> <count>` submits one addressed FC03 for a contiguous span of documented words. Show the register and raw 16-bit value of each returned word in order. Range-containing spans may initiate measurement. Multi-word behavior and sampling coherence are unverified. |
| Commissioning | `maintenance [on isolated\|off]` shows or requests bench-owner admission. `config set <key> <value> [confirm]` performs an addressed write and readback. `setaddr <address> [confirm]` and `setbaud <rate> [confirm]` are aliases. `broadcast set <key> <value> [confirm]` sends the DFRobot vendor form on a dedicated isolated bench. A preview shows plan, register, raw word, address policy, endpoints and verification steps with zero I/O. Confirmation uses stage 05 validation, one owner-admitted grant and stage 07 scheduling. |
| Jobs | `job status` reports the active or most recent generation, phase and deadline. `result [op]` returns the retained terminal result for that generation or reports its absence. `cancel [op]` (`stop`) requests cooperative cancellation. Reject an explicitly stale ID. Stopping new requests, draining a transmitted request, write uncertainty and cleanup completion have separate observable outcomes. |
| Diagnostics | `diagnose` (`diag`) reads the selected unicast slave-address register and reports expected/observed address, elapsed time and any Modbus exception. A matching value provides addressed communication evidence only. `recover` services the host UART/transport recovery policy and reports its outcome. `selftest` exercises offline published frame vectors with zero sensor I/O. |

The four read kinds are `0x0100` processed mm, `0x0101` real-time mm, `0x0102` raw temperature in 0.1 °C units, and `0x010A` echo µs. Show raw words, source register, binding, sample generation, observation timestamp, age in ms and validity/freshness per kind. A positive example can display °C alongside the raw word. Preserve ambiguous temperature encodings in raw form. Echo distance is an explicitly approximate conversion. Keep previous good data and its age visible after failure. An address match, a valid exception, an FC06 echo or reading a configuration word cannot publish a measurement. [Measurements and settings](../reference/measurement-and-configuration.md) · [Register map](../reference/protocol/registers.csv)

`readregs` accepts decimal counts 1–125 and checks every address in the span before TX. The longest contiguous span in the published inventory is three words. Examples include `readregs 0x0100 3` and `readregs 0x0205 2`. Reject zero, overflow, a missing register anywhere in the span, arithmetic wrap or a broadcast destination. Use the portable public diagnostic builder and exact expected-count parser. The returned words belong to this single live operation. Even a one-word diagnostic keeps typed samples, freshness and observed/trusted configuration untouched. A complete attributable exchange can still inform communication health. Report the owner's finite `timeoutMs` budget including conservative latency for all included measurements, serial time, turnaround and frame closure. Configuration execution time and combined sensor latency are unspecified. Keep the console responsive, return the actual exception or timeout, and send no automatic retry or single-register fallback. [FC03 layout and device evidence](../reference/protocol/Modbus_RTU_notes.md#frame-layout)

## Configuration commands for both example applications

Implement this table in full on Arduino and ESP-IDF. All eight keys take the same read, preview, confirmed addressed write and explicit vendor broadcast command forms. Encode validated values with the public sensor library. The CLI parses operator units and renders results. Every group, key and permitted value is discoverable through ordinary human help on the running example. Replay each addressed row through its named command in the [operation matrix](OPERATIONS.csv). Add the eight isolated send-only cases separately.

| Register | Key | Accepted command value and result |
| --- | --- | --- |
| `0x0200` | `address` | Decimal slave address. Standard 1–247, isolated manufacturer policy 1–254. An addressed change verifies the raw address word at the proposed new endpoint. |
| `0x0201` | `baud` | Baud/s 4800, 9600, 14400, 19200, 38400, 57600, 76800 or 115200. Show the corresponding raw code 2–9 and verify this word at the new baud. |
| `0x0205` | `polarity` | 0 for low or 1 for high below the switch threshold. Show the active switch-mode interpretation and raw word. Equality behavior is unspecified. |
| `0x0206` | `threshold` | Distance in mm, 30–3000 on SEN0591 or 30–5000 on SEN0592. The result is a switch-mode threshold setting. |
| `0x0208` | `angle` | Level 1–4. Resolve approximate single angle or dual horizontal/vertical values for the selected model. |
| `0x0209` | `uart-unit` | `mm` or `us`, encoded as 0 or 1. Label the setting “automatic/controlled UART output.” Keep the unit of every RS485 measurement fixed by its measurement register. |
| `0x021A` | `noise` | Level 1–5. Show the reported level and manufacturer supply/noise context. |
| `0x021F` | `range` | Level 1–4 for SEN0591 or 1–5 for SEN0592. Show both approximate level distance and SKU-rated range. |

For the three mode-specific settings, execute the real FC06 and same-register FC03 readback through the typed API. Report exactly what the unit returned, including a valid device exception. Successful readback proves the register value. The four-wire RS485 model has no documented switch pin or command for activating automatic/controlled UART output. Its physical behavior in those modes is unverified. Ordinary writes use the same endpoint for readback. Address or baud changes use the new endpoint. A lost ACK, uncertain local echo or mismatched readback preserves the separate operation, endpoint and trust evidence. Power-cycle persistence needs a separate physical observation. [Configuration evidence](../reference/measurement-and-configuration.md#configuration-on-the-rs485-models)

`profile standard` is the default and uses `AddressPolicy::StandardUnicast`. `profile dfrobot-isolated` explicitly selects `AddressPolicy::DFRobotIsolated` for a dedicated single-device bench and makes its extended reply/target range available. Show the selected profile in help, `status` and commissioning plans. Changing profiles requires an idle owner and compatible current address. To return from a high address, restore or select a standard address before changing profile. Reject target/assigned addresses 0 and 255 under both policies. `broadcast set` is a separate explicit destination 255 available only under the isolated policy. Both bench adapters must support the eight documented sensor rates. The distinct FieldCore fixture exercises its own five-rate limit.

For confirmed `broadcast set`, send exactly one checked FC06, settle TX/RX under the owner's policy, bound the drain, and record observable bytes, including possible echo or unexpected RX. An ordinary send completion proves local transmission only. A reply, addressed device effect and persistence are unestablished. End the send-only request with `verified=false`. A later explicit `config read <key>` at the intended addressed endpoint provides independent evidence. A baud/address change may require local `host baud` or `useaddr` first. Keep the original result immutable. There is no broadcast FC03 or automatic rewrite. The examples accept published register keys through their typed builders. [Vendor and Modbus address definitions](../reference/protocol/Modbus_RTU_notes.md#serial-settings-and-addressing)

On a dedicated bench, `maintenance on isolated` records the operator's declaration that one unit is physically isolated. It cannot detect bus topology. Bind the grant to the selected SKU/address/baud and session, consume it on admission of one write, and expire it after 60 seconds of inactivity or any change of binding/session. `maintenance off` relinquishes a grant and leaves the outcomes of earlier transmissions intact. A larger application may refuse admission while sharing the link. Report `DISALLOWED` with a reason and zero TX. A preview works in all cases, including when maintenance is closed.

Use `[I]` and `[E]` for human responses. Print the literal code using `errToString`, signed `Status.detail` and human-readable `Status.msg` when available. Include the raw exception byte and decoded Modbus name. Use `driverStateName` and the exact health fields in [CONVENTIONS](CONVENTIONS.md). Example human interaction below uses simulated input. The strings after `[I]` illustrate the information required. Publish transcripts produced by the actual dispatcher in stage 09.

```text
> help read
read <processed|realtime|temperature|echo>    Start one live read at the selected address.
> model SEN0591
[I] Model SEN0591, address 1, 115200 baud 8N1
> read realtime
[I] Accepted operation 7, SEN0591 address 1, register 0x0101
[I] Operation 7 OK, real-time distance 428 mm, raw 0x01AC
> latest realtime
[I] 428 mm, SEN0591 address 1, generation 7, age 24 ms, valid, fresh
> setaddr 3

> config set threshold 300
[I] Preview only. SEN0591 switch-mode threshold 300 mm, register 0x0206, word 0x012C.
```

## Parser and cooperative service

Use a 192-byte input line limit excluding terminator, at most 10 tokens and 64 bytes per token. Use ASCII space/tab as token separators, CR/LF/CRLF as one logical terminator and backspace/DEL to edit a valid pending line. Use the exact case-sensitive command words, aliases, profile names and setting keys shown above. Accept the literal model tokens `SEN0591` and `SEN0592`. Parse decimal integers and explicit `0x` hexadecimal register addresses with upper- or lowercase hex digits. Require the entire token, arity and numeric range. Reject embedded control bytes, non-ASCII input, overflow, negative/out-of-range values and trailing text. After malformed input or overflow, discard through the terminator, then process a clean line. Never dispatch a truncated prefix. A static admission failure causes zero bus I/O and preserves settings, samples and counters of completed sensor work.

Command service, polling and output flushing each do bounded work per turn with fixed-capacity buffers. Own any data retained after the handler returns. Keep the owner responsive throughout the longest measurement, UART stalls and console backpressure. Reserve room for each terminal record before admitting work or retain it until delivery. Bound the size of each response. Use topic help and command-specific result projections for longer reports. Track dropped ordinary output separately. Do not log to the console from an interrupt, codec callback or bus transaction lock.

## Machine channel for the host runner

- Machine input is `@<req> <command>`. Require a nonzero unsigned decimal request ID from 1 through 4294967295. Plain commands remain human. A valid machine request receives machine output only. New sessions attach using `@1 session <nonce>`, with 1–32 ASCII letters, digits, underscores or hyphens. Supply a new nonce for each attachment. Echo the nonce and return build identity, target/baud, current operation and schema with no sensor I/O.
- Frame each output at column zero as the exact eight-byte ASCII prefix `SEN059X `, one UTF-8 JSON object, and LF. When a prompt or partial human line is open, terminate that line before the prefix. No colors, timestamps, log tags, prompts or interleaved console bytes inside a machine record. Maximum 2048 bytes including prefix and LF. Escape strings using JSON rules and preserve complete records under partial writes.
- Every record has `v` (integer 1), `boot` (16 lowercase hexadecimal characters chosen anew at boot), `session` (nonce, null before attachment), `req` (request ID), `phase` (`accepted` or `done`), `cmd` (canonical command name), `op` (positive operation generation or null), `code`, `detail`, and `data` (an object). Canonical names include `job status` and `config read`. The canonical name of a measurement request is `read`, with its kind in `data`. Echo a bounded unknown command in `cmd` on rejection. Use `code: null` and `detail: null` on admission. Terminal `code` is the literal public status string and `detail` is signed integer `Status.detail` with zero when unused. Include status message and primary/cleanup/verification details in `data` when available.
- For a new request with valid framing and ID, local commands, previews and static rejections produce exactly one `done`. Before session attachment, reject machine commands other than the handshake. Each admitted live operation produces one `accepted` and one eventual `done` with its original boot/session/request/op. Bind a finite watch to one parent operation with measured child request counts. Return typed results with model, slave, register, raw value, units, sample generation, age/validity/freshness and elapsed time as applicable. An asynchronous terminal includes `data.disposition` using the stage 08 result literals (such as `Ok`, `Timeout`, `Cancelled`, `Failed`). An admitted cancel control request may return `OK` under its own ID. When cancellation terminates the original operation, its terminal uses `ABORTED` plus `Cancelled` and includes any prior transfer effects and cleanup result. A late cancel leaves a retained completed result intact. Require both successful disposition and status for a successful operation. Include phase, evidence, elapsed time and availability of earlier cached data on failure. Protect each admitted operation against overwriting a pending terminal record.
- Reserve unique IDs per session. The runner increments monotonically and starts a new session before wrap. Ignore reused or out-of-order IDs in an established session, count the protocol error locally and emit no second terminal for the same ID. The nonce-changing handshake starts a new sequence. While the owner is busy permit passive queries and cancellation under their own IDs. Retain at least the last completed operation until replacement as documented in `result`. A session handshake cannot cancel, rebind or relabel previously admitted work. Emit its terminal record with its original session and report the pending or retained generation to the new session. A reboot changes `boot` and invalidates all old work. A client timeout, disconnect or missing record proves no terminal outcome.
- The runner discards non-record lines. A malformed prefixed line, unknown schema, duplicate terminal, reboot mid-operation, missing terminal or mismatched ID/session/op cannot prove success. The host must not replay measurement triggers or writes to repair evidence. Exercise delayed/stale records and reconnect through `session`, `job status` and `result`. Bound failure on incomplete lines and prove recovery at the next line.

Use these `data` fields where applicable. Encode addresses, RTU register numbers and raw words as JSON integers, with nullable data for unknown observations.

| Command/result | Required data |
| --- | --- |
| `session`, `version` | `libraryVersion`, `libraryRevision` (commit or `unknown`), `libraryDirty` (bool or null), `firmwareRevision`, `dirty` (firmware, bool or null), `framework`, `frameworkVersion`, `target`, `board`, `model` (null or literal SKU), `addressPolicy` (`standard` or `dfrobot-isolated`), `address`, `baud`, `supportedBaud` (array), `serialFormat` (`8N1`), `activeOp` (nullable). Take library, firmware and framework metadata from their respective build artifacts. [Version contract](VERSIONS.md) |
| `read`, `latest <kind>` | Use a `sample` object or null. Fields are `model`, `address`, `bindingGeneration`, `kind`, `register`, `raw`, `value` (number or null), `unit` (`mm`, `degC`, `us`), `quality`, `sampleGeneration`, `observationMs`, `ageMs`, `valid` and `fresh`. Unknown time/age is null and freshness is unproven. Optional `approxDistanceMm` on echo accompanies the primary duration. `latest` without a kind returns `samples` keyed by all four kinds. A failed read can expose a retained sample as `previousSample`, distinct from `sample` for the attempted generation. |
| `readregs` | `model`, `address`, `bindingGeneration`, `startRegister`, `count`, `timeoutMs` and terminal `words`. On success return exactly `count` unsigned 16-bit words in ascending register order. On an exception, timeout, incomplete or invalid reply return `words=null` and the operation error/detail. The diagnostic emits no typed sample or per-word acquisition timestamp. |
| Live terminal, `job status`, `result` | For a terminal operation report `disposition`, `elapsedMs`, `transfers`, `attempts` and optional `cleanupCode`/`cleanupDetail`. Passive `job status` includes `active` and includes the operation identity and deadline when busy. `result` reports the original `boot`, `session`, `req`, `op`, `cmd` and terminal payload nested inside its own response. `cancel` identifies the targeted operation and its cancellation stage. |
| `config read`, `settings` | Each setting supplies `key`, `register`, `raw` (uint16 or null), `value` (decoded or null), `applicability` (`rs485`, `switch-mode` or `uart-output`), observation validity, endpoint and readback trust. Preserve unfamiliar or out-of-profile raw values. `config read` refreshes one word. `settings` reports the eight cached entries. |
| Writes and watch | Addressed writes return canonical `cmd="config set"`, including aliases. Broadcast uses `cmd="broadcast set"`. Report `key`, `register`, `requested` (encoded word), `observed` (matching-register FC03 raw word or null), `destination`, `scope` (`addressed` or `send-only`), `acknowledged`, `verified`, `effectUncertain` and old/new endpoints as applicable. An isolated broadcast's terminal can report successful local TX and `observed=null`, `acknowledged=false`, `verified=false`, `effectUncertain=true`. An independent addressed read has its own request and result. Watch returns `requested`, `completed`, `failed`, `skippedIntervals` and the last attempt/result. |
| Health and stats | Preserve the exact `HealthSnapshot` and owner counter names in [CONVENTIONS](CONVENTIONS.md). Render each stored status as code, signed detail and message. Keep locally unknown timestamps distinguishable from timestamp zero. |
