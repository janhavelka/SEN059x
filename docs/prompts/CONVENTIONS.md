# Public names and ownership

Use the SHZK-PT shape at the point where FieldCore builds a request and accepts a reply. Use the TMP1x2 vocabulary where an application inspects a device's health. These are planned SEN059x contracts for the numbered prompts. The links identify implemented peer declarations and the TMP11x planning precedent.

## Values and codec

| Source convention | SEN059x contract |
| --- | --- |
| SHZK-PT exports a package-scoped include and namespace. The TMP11x promptset specifies explicit family variants. | Include `<SEN059x/SEN059x.h>` and use namespace `SEN059x`. The caller selects `DeviceModel::SEN0591` or `DeviceModel::SEN0592`. No default model. Use self-contained headers, PascalCase types, camelCase functions and arguments, and CAPS_CASE protocol constants. |
| SHZK-PT uses `Err : uint16_t`, `Status`, free `Ok()`, predicates `ok()` and `isOk()`, and explicit boolean conversion. MotorControl-RS uses a smaller underlying enum and the same free factory. VibWire's `Status::ok()` is a static factory. TMP1x2 has `Status::Ok()`. | Follow SHZK for all five entry points. `Status` carries `Err code`, **signed** `int32_t detail`, and `const char* msg` with static lifetime. Default construction and `Ok()` mean `OK`, detail zero and an empty message. `errToString(Err)` returns the uppercase enum spelling or `"UNKNOWN"`. `modbusExceptionToString(uint8_t)` supplies human text. Branch on enums. |
| SHZK-PT provides `calcCrc16`, `isValidAddress`, `buildReadRegisters`, `validateReadResponseExpected`, `buildWriteSingleRegister`, and `parseWriteSingleRegister`. FieldCore uses the expected address and count and maps `ReadResponseError` directly. | Preserve those names and caller-buffer/length conventions. The device-facing builders accept only published one-word operations. The checked write builder also takes the explicit model for value bounds. Keep outputs unchanged on rejected responses. Retain the requested register outside the parser. |
| SHZK uses `Baud`, `baudToValue`, `valueToBaud`, `baudToString`. | Use checked conversions for the **SEN059x** eight-code table. Distinguish a register code from baud/s. An unknown code stays observable and conversion reports failure. |

The exact broad result set and who can supply each result follow. Numeric values beyond `OK = 0` are SEN059x implementation details until explicitly documented. Lower-layer numeric values use signed `detail`. A checked Modbus exception stores its unmodified byte in the range 0–255. | Planned `Err` | Meaning and producer |
| --- | --- |
| `OK` | The operation described by the call succeeded. Building bytes, validating a reply and verifying a configuration are separate operations. |
| `INVALID_CONFIG`, `ILLEGAL_VALUE`, `UNSUPPORTED` | Bad arguments/binding, value beyond a documented setting's limits, or a register/access/feature outside the profile, respectively. |
| `CRC_ERROR`, `FRAME_ERROR`, `EXCEPTION` | Bad CRC, incomplete or mismatched reply, or validated exception with the raw code in `detail`. |
| `NOT_INITIALIZED`, `BUS_BUSY`, `TIMEOUT`, `IO` | Owner lacks an active binding, cannot admit an exchange, misses the response deadline, or reports a platform I/O error. Surface the original platform detail where available. |
| `NO_DATA`, `DISALLOWED`, `ABORTED` | Owner has no requested sample yet, a local write policy rejected admission, or an admitted operation terminated through cancellation. Record TX progress, cleanup and any uncertain effects separately. |
| `CONFIG_MISMATCH`, `LINK_LOST` | A valid FC03 readback differs from the requested value, or the owner could not establish the post-change endpoint. Keep the underlying failure and observations available. |

Use SHZK's exact `ReadResponseError : uint8_t` members `NONE`, `INVALID_ARGUMENT`, `FRAME_TOO_SHORT`, `CRC_MISMATCH`, `UNEXPECTED_ADDRESS`, `UNEXPECTED_FUNCTION`, `EXCEPTION_RESPONSE`, `BYTE_COUNT_MISMATCH`, and `LENGTH_MISMATCH`. Give callers this structured detail as well as broad status. VibWire's `BAD_LEN/BAD_RESP/RANGE/CRC` map onto this shape. Preserve `IO`, `DISALLOWED` and `ABORTED` for their actual owner cases. TMP1x2 and DP8382x supply the preceding `CONFIG_MISMATCH` precedent. Pending, cancelling and retrying belong to the owner operation lifecycle. SHZK's `DISCONNECTED` assumes a known sensor sentinel, `INVALID_CHANNEL` a multichannel device, and `ROLLBACK_FAILED` a rollback procedure. SEN059x has evidence for none of those behaviors. ## Health, statistics and consumer ownership

| Peer evidence | Adopted names and counting unit |
| --- | --- |
| TMP1x2 and DP8382x expose four passive device states. TMP1x2 uses millisecond timestamps and a separately valid timestamp bit for each. | `DriverState::{UNINIT, READY, DEGRADED, OFFLINE}`, `driverStateName` (uppercase or `"UNKNOWN"`), `state()`, `isOnline()`, `healthSnapshot()`, `resetStatistics()`. One caller-owned `DeviceHealth` per binding. It accepts completed exchange observations. |
| TMP1x2 `HealthSnapshot` | `state`, `initialized`, `consecutiveFailures` (uint8_t), `totalFailures`, `totalSuccess`, `lastOkMs`, `lastErrorMs` (uint32_t), `lastOkTimeValid`, `lastErrorTimeValid`, and `Status lastError`. Totals count tracked exchange outcomes. Saturate. `lastError` retains the most recent communication failure after recovery. `resetStatistics()` clears the two cumulative totals. |
| SHZK passive `Stats` | Owner-maintained `successCount`, `failCount` (completed logical operations), `retryCount` (extra attempts actually sent), and `crcErrors`, `timeouts`, `exceptions`, `frameErrors` (observed attempt errors). Keep `lastError` (an `Err`), `lastErrorDetail`, `lastErrorMsg`, `lastErrorTimestampMs`, and `lastSuccessTimestampMs` together. `Stats::reset()` resets owner statistics. State which endpoint or bus and interval they cover. |
| FieldCore's `HealthState`, `HealthRole`, `PresenceState` | The application assigns `Initializing/Ok/Degraded/Fault/Unknown/Disabled`, `Required/Optional`, and `Unknown/Present/Absent/Disabled` respectively. Preserve its lowercase health strings and firmware policy at the adapter. |

In the FieldCore fixture, use `healthStateName` to display `initializing`, `ok`, `degraded`, `fault`, `unknown`, `disabled`. Use `presenceStateName` for `unknown`, `present`, `absent`, `disabled`. A product request moves through `Rs485RequestLifecycle::{NotFound, Queued, Running, ResultReady}`. The shared owner reports `Rs485BusState::{Idle, Transmitting, WaitingResponse, WaitingDevice, Fault}`. These describe a request and a bus. The per-device `DriverState` remains independently observable while a peer is using that bus. [FieldCore health names](https://github.com/janhavelka/FieldCore-node/blob/eccdbdcc0e9ce22beee4f54494c6c179a320d3aa/include/TunnelMonitor/contracts/Health.h) · [FieldCore bus and request states](https://github.com/janhavelka/FieldCore-node/blob/eccdbdcc0e9ce22beee4f54494c6c179a320d3aa/include/TunnelMonitor/contracts/Rs485Devices.h)

An exact addressed exception proves a responding link and fails the sensor operation. It increments physical `totalSuccess` and the owner's `exceptions`. If terminal, it increments `failCount`. Preserve the exception as the operation result. An FC06 echo can prove a link only when the owner has excluded its own transmit echo. A local builder failure, display of a cached sample or admission rejection yields zero exchange events.
