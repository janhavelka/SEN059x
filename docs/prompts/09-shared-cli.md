# 09 — Implement the shared bench console

## Inputs

Apply [COMMON](COMMON.md), the [CLI contract](CLI_CONTRACT.md) and the [public conventions](CONVENTIONS.md). Consume `device-health`, `owner-contract` and `consumer-fixture`. This stage produces `shared-cli`. Inspect the pinned command tables and dispatchers in the CLI contract and [source map](SOURCE_MAP.md).

## Work

1. Put the framework-independent example processor, bounded line editor, registry, formatting and dispatch in `examples/common/`. The only dependencies for a native build are the standard C++ library, SEN059x and the application-side owner types. Use injected hooks for console output, clock, boot/build identity, board capabilities and commissioning admission. Keep example code outside library exports.
2. Implement every command and alias in the contract. From one registry, provide discoverable grouped help, per-command usage and a checked command list for both example READMEs. Specify arity, units, supported models and local/cached/live/commissioning effects. A preview, help, health or latest query must work with a fake port that fails any attempted I/O.
3. Route live work through the normal owner entry point. Keep each pending operation's request ID, generation, model, target, register/expected value, deadline and terminal storage alive. Allow passive queries and cancellation during a long processed read. Keep cancellation, write readback, late-reply settlement, retained data and primary/cleanup results observable. Give previews and failed admissions zero bus effects. Keep sessions and local target changes isolated.
4. Implement both renderers and the versioned runner handshake. In human mode show text that an operator can use with a serial terminal. In machine mode implement exact framing, correlation, terminal reservation and signed status detail from the [CLI contract](CLI_CONTRACT.md). Add a short operator reference, a human transcript and machine examples from the real dispatcher running against a scripted owner.
5. Implement the contract's eight named settings with one typed public-library operation per read/write. Show legal values and register meanings for the selected SKU. Route `readbaud`, `setaddr` and `setbaud` through their canonical handlers. Expose `profile dfrobot-isolated`, an extended-addressed read/write path, and `broadcast set` as an explicit send-only operation. Route conditional switch and UART settings through the same real transfer/readback path as angle and range. A help entry, placeholder handler or simulated “OK” alone leaves that feature incomplete.

## Acceptance

- Compile the shared C++ sources and dispatch them in the native test target using a fake UART, clock, capped output sink and fixed boot ID. Feed complete command streams through the line editor and dispatcher.
- Prove help/registry/docs agree, aliases resolve identically and arity, maximum length, CR/LF, editing, bad integers, overflow poison, unknown registers and unsupported rates have defined outcomes. After a malformed line send a valid one and verify it works.
- Make a table-driven parity test for both SKUs and both renderers. Derive expected addresses/access from the audited [register CSV](../reference/protocol/registers.csv) and the [operation cases](OPERATIONS.csv). Use the six published exchanges as manufacturer vectors. Independently derive expected frames for the remaining synthetic cases. Exercise four named live reads, all twelve numeric `readreg` commands, eight named configuration reads, eight addressed write previews and confirmations, and eight vendor send-only previews and confirmations. Compare the exact TX ADU, raw/decoded output, SKU, status and number/order of FC03 and FC06 calls. An addressed success requires independent readback. A broadcast success can prove only its TX stage. Test both address/baud aliases and both mode-specific polarities, units and threshold limits.
- Exercise the eight baud settings and register-code conversions. Under the default standard policy reject addresses 248–255, and reject every broadcast attempt before TX. Under the explicitly isolated vendor profile, use 248 and 254 as source and destination endpoints, assign a high address, read it back, then restore a standard address. Reject 0 and 255 as assigned or ordinary target addresses. Assert out-of-range input, stale grant or wrong policy leaves the bus silent. Confirm a valid exception from a mode-specific register reaches the console with its byte and leaves the earlier observed value intact.
- Drive the raw `readregs <start> <count>` command via both renderers. For `0x0100 3` and `0x0205 2` match the exact FC03 request, one whole response, ordered raw words and finite reported budget. For a valid device exception, timeout or wrong byte count require zero published words and one request with no fallback. Reject a hole, wrap, zero, count 126 and broadcast with zero TX. Compare cached samples and observed configuration before/after each case, including a count-one diagnostic. Do not infer simultaneous measurement from a block.
- Keep separate cases for a positive temperature, ambiguous raw temperature, independent echo sample, stale cache, SKU-specific range, exact exception, wrong FC06 echo and uncertain write. Assert units, named status, sample/health counters and per-command transfer counts.
- Interleave a finite watch or delayed read with `health`, `job status`, a second live request and `stop`. Submit an old generation, rebind, repeat a request ID, reattach during pending work and stall the sink across completion. Assert one attributable terminal per admitted request and drain/cleanup evidence. The half-open operation must survive operator and runner backpressure.
- Capture a human transcript from the prompt through help, selection, live read, failed read, retained last-good age and `drv`. Include a switch or UART write with exact raw readback and a vendor send-only operation followed by an explicit addressed read. Capture the corresponding JSON session and terminal failure with signed detail. Publish the executable replay commands, with synthetic/physical origin identified for each recording.
