The named libraries serve different roles. SHZK-PT is the direct Modbus API precedent. TMP1x2 supplies the working per-device health and CLI vocabulary. The consumer owns scheduling, serial format and product health. The [conventions table](CONVENTIONS.md) records each literal name retained or adapted. The [shared console](CLI_CONTRACT.md) defines the SEN059x grammar and its differences from the individual examples.

FieldCore's profile pins SHZK-PT v3.0.0 to `361c47c` and VibWire-108 v1.2.0 to `9365df6`. Compare the current sibling heads above with those versions for compatibility-sensitive calls. Neither inspected product profile enables SEN059x. Stage 08 checks its two prospective consumer contracts offline. [FieldCore profile](https://github.com/janhavelka/FieldCore-node/blob/eccdbdcc0e9ce22beee4f54494c6c179a320d3aa/config/build_profiles.json) · [SHZK v3.0.0 header](https://github.com/janhavelka/SHZK-PT/blob/361c47c0588fe967e9dc5507ce7a3d85a2f0eb6a/include/SHZK_PT/SHZK_PT.h) · [VibWire v1.2.0 header](https://github.com/janhavelka/VibWire-108/blob/9365df6a51800755f417a1fa251088ee42be9dc0/include/VibWire/VibWire.h)

For the consumer proof, follow a queued request from the binding through the bus owner and the UART backend, then back to the retained result. VibWire shows how a module yields time between exchanges. The backend determines which timing and local-echo facts are available to the parser.
